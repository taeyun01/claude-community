- 작성일: 2026-08-18
- 기술스택: Next.js, Supabase (Auth/DB/Storage), Tailwind CSS, Vercel (배포)

## 2. 각 기능 상세 요구사항

### 2.1 회원가입 (FR-101)
- 이메일 + 비밀번호 기반 회원가입 (Supabase Auth 사용)
- 필수 입력: 이메일, 비밀번호, 비밀번호 확인, 닉네임
- 이메일 형식 검증, 비밀번호 최소 8자 이상
- 닉네임 중복 확인 (`profiles` 테이블 조회)
- 가입 성공 시 `profiles` 테이블에 초기 프로필 레코드 생성 (닉네임, 기본 프로필 이미지)
- 가입 성공 시 자동 로그인 처리 후 홈 피드로 이동
- 이메일 인증 사용 여부는 정책에 따라 선택 (초기 버전은 이메일 인증 생략 가능)

### 2.2 로그인 (FR-102)
- 이메일 + 비밀번호 로그인 (Supabase Auth `signInWithPassword`)
- 로그인 실패 시 에러 메시지 표시 (이메일/비밀번호 불일치, 미가입 계정 등)
- 로그인 성공 시 세션 저장 후 홈 피드로 이동
- 비로그인 상태에서 글 작성, 댓글, 좋아요, 프로필 수정 등 접근 시 로그인 화면으로 리다이렉트

### 2.3 로그아웃 (FR-103)
- 설정 탭 내 로그아웃 버튼 제공
- 로그아웃 확인 다이얼로그 표시 후 세션 종료
- 로그아웃 후 로그인/홈(비로그인 상태) 화면으로 이동

### 2.4 글 작성 (FR-201)
- 로그인 사용자만 접근 가능
- 입력 항목: 제목, 본문 (텍스트), 이미지 첨부(선택, Supabase Storage 업로드)
- 제목/본문 필수 입력 검증 (빈 값 방지)
- 작성 완료 시 `posts` 테이블에 저장, 작성자 정보(user_id) 자동 연결
- 작성 완료 후 상세 화면 또는 목록 화면으로 이동

### 2.5 글 목록 조회 (FR-202)
- 홈 탭에서 최신순 피드 형태로 게시글 노출
- 목록 항목: 작성자 닉네임/프로필이미지, 제목, 본문 일부 미리보기, 대표 이미지(있는 경우), 좋아요 수, 댓글 수, 작성 시각
- 무한 스크롤 또는 페이지네이션으로 목록 로드
- 비로그인 사용자도 목록/상세는 조회 가능 (읽기 전용)

### 2.6 글 상세 조회 (FR-203)
- 게시글 원문(제목, 본문, 이미지), 작성자 정보, 작성/수정 시각 표시
- 좋아요 수 및 내가 좋아요 눌렀는지 여부 표시
- 댓글 목록 및 댓글 작성 영역 노출
- 작성자 본인인 경우 수정/삭제 버튼 노출

### 2.7 글 수정 (FR-204)
- 작성자 본인만 접근/수정 가능 (권한 검증)
- 작성 화면과 동일한 입력 폼 재사용, 기존 값 프리필
- 수정 완료 시 `updated_at` 갱신 후 상세 화면으로 이동

### 2.8 글 삭제 (FR-205)
- 작성자 본인만 삭제 가능
- 삭제 전 확인 다이얼로그
- 삭제 시 연관된 댓글/좋아요 데이터도 함께 삭제(cascade) 또는 소프트 삭제 정책 적용
- 삭제 후 목록 화면으로 이동

### 2.9 댓글 작성 (FR-301)
- 로그인 사용자만 작성 가능
- 빈 댓글 등록 방지
- 작성 시 `comments` 테이블에 게시글 id, 작성자 id, 내용, 작성 시각 저장
- 작성 완료 즉시 댓글 목록에 반영 (낙관적 업데이트 권장)

### 2.10 댓글 목록 조회 (FR-302)
- 게시글 상세 화면 하단에 시간순(오래된순 또는 최신순) 목록 표시
- 댓글 작성자 닉네임/프로필이미지, 내용, 작성 시각 표시

### 2.11 댓글 삭제 (FR-303)
- 댓글 작성자 본인만 삭제 가능
- 삭제 전 확인 다이얼로그
- 삭제 시 목록에서 즉시 제거

### 2.12 게시글 좋아요 (FR-401)
- 로그인 사용자만 좋아요 가능
- 게시글당 사용자 1회만 좋아요 가능 (`likes` 테이블에 user_id + post_id 유니크 제약)
- 좋아요 버튼 토글 방식 (누르면 추가, 다시 누르면 취소)
- 좋아요 수는 실시간(또는 낙관적 업데이트)으로 화면에 반영

### 2.13 내 프로필 조회 (FR-501)
- '내 정보' 탭에서 본인 프로필 확인
- 표시 항목: 프로필 이미지, 닉네임, 이메일(선택 노출), 내가 쓴 글 수, 내가 쓴 글 목록

### 2.14 프로필 수정 (FR-502)
- 닉네임 변경 (중복 확인 필수)
- 프로필 이미지 변경 (Supabase Storage 업로드, 기존 이미지 교체)
- 저장 시 `profiles` 테이블 업데이트

### 2.15 내가 쓴 글 목록 조회 (FR-503)
- '내 정보' 탭 내 목록 형태로 본인이 작성한 게시글만 필터링하여 표시
- 각 항목 클릭 시 해당 글 상세로 이동

### 2.16 다른 유저 프로필 보기 (FR-504)
- 게시글/댓글의 작성자 닉네임 또는 프로필 이미지 클릭 시 해당 유저 프로필 화면으로 이동
- 표시 항목: 프로필 이미지, 닉네임, 해당 유저가 작성한 글 목록
- 본인 프로필과 달리 수정 버튼은 노출하지 않음 (읽기 전용)

### 2.17 하단 탭 내비게이션 (FR-601)
- 3개 탭: 홈(피드) / 내 정보(프로필) / 설정
- 비로그인 상태에서 '내 정보' 탭 접근 시 로그인 화면으로 유도
- 현재 활성 탭 하이라이트 표시

### 2.18 설정 화면 (FR-602)
- 로그아웃 버튼
- (선택) 계정 정보, 앱 버전, 문의하기 등 부가 메뉴

## 3. 사용자 흐름

### 3.1 회원가입 → 로그인 흐름
```
[앱 진입]
  → (비로그인) 홈 피드 열람 가능
  → '내 정보' 탭 또는 글 작성 시도
  → 로그인 화면으로 이동
  → "회원가입" 선택
  → 이메일/비밀번호/닉네임 입력
  → 가입 완료 → 자동 로그인 → 홈 피드 이동
```

### 3.2 로그인 흐름
```
[로그인 화면]
  → 이메일/비밀번호 입력 → 로그인 버튼
  → 성공: 홈 피드로 이동
  → 실패: 에러 메시지 표시, 재입력
```

### 3.3 글 작성 흐름
```
[홈 피드] → 글쓰기 버튼(FAB 등) 클릭
  → (비로그인이면 로그인 화면으로 리다이렉트)
  → 글 작성 화면: 제목/본문/이미지 입력
  → 등록 버튼 클릭 → 유효성 검증
  → 저장 성공 → 글 상세 화면으로 이동
```

### 3.4 글 상세 → 댓글/좋아요 흐름
```
[홈 피드] → 게시글 클릭 → 글 상세 화면
  → 좋아요 버튼 클릭 → (비로그인이면 로그인 유도) → 좋아요 토글
  → 댓글 입력창에 내용 작성 → 등록 → 댓글 목록에 즉시 반영
  → 작성자 닉네임/이미지 클릭 → 해당 유저 프로필 화면 이동
```

### 3.5 프로필 조회/수정 흐름
```
[하단 탭 '내 정보'] → 내 프로필 화면
  → 프로필 정보(닉네임/이미지) 및 내가 쓴 글 목록 확인
  → '프로필 수정' 버튼 클릭
  → 닉네임/이미지 변경 → 저장 → 프로필 화면 갱신
```

### 3.6 다른 유저 프로필 보기 흐름
```
[홈 피드 또는 글 상세] → 다른 사용자 닉네임/이미지 클릭
  → 해당 유저 프로필 화면 (읽기 전용)
  → 해당 유저가 쓴 글 목록 확인 → 글 클릭 시 상세 이동
```

### 3.7 로그아웃 흐름
```
[하단 탭 '설정'] → 로그아웃 버튼 클릭
  → 확인 다이얼로그 → 확인
  → 세션 종료 → 홈 피드(비로그인 상태)로 이동
```

## 5. 간단한 데이터 개요

Supabase(PostgreSQL) 기준 테이블 구조 개요.

### 5.1 profiles (사용자 프로필)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid (PK, FK → auth.users.id) | Supabase Auth 사용자 id |
| nickname | text (unique) | 닉네임 |
| avatar_url | text (nullable) | 프로필 이미지 URL (Storage) |
| created_at | timestamptz | 생성 시각 |
| updated_at | timestamptz | 수정 시각 |

### 5.2 posts (게시글)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid (PK) | 게시글 id |
| user_id | uuid (FK → profiles.id) | 작성자 |
| title | text | 제목 |
| content | text | 본문 |
| image_url | text (nullable) | 첨부 이미지 URL |
| created_at | timestamptz | 작성 시각 |
| updated_at | timestamptz | 수정 시각 |

### 5.3 comments (댓글)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid (PK) | 댓글 id |
| post_id | uuid (FK → posts.id) | 대상 게시글 |
| user_id | uuid (FK → profiles.id) | 작성자 |
| content | text | 댓글 내용 |
| created_at | timestamptz | 작성 시각 |

### 5.4 likes (좋아요)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid (PK) | 좋아요 id |
| post_id | uuid (FK → posts.id) | 대상 게시글 |
| user_id | uuid (FK → profiles.id) | 좋아요 누른 사용자 |
| created_at | timestamptz | 생성 시각 |
| | | unique(post_id, user_id) 제약 |

### 5.5 관계 요약
- `auth.users` 1:1 `profiles`
- `profiles` 1:N `posts`
- `posts` 1:N `comments`
- `posts` 1:N `likes` (단, `user_id` + `post_id` 조합은 유니크)
- Row Level Security(RLS): 각 테이블에서 본인 작성 데이터만 수정/삭제 가능하도록 정책 설정, 조회(SELECT)는 공개 데이터에 한해 전체 허용

### 5.6 Storage
- `avatars` 버킷: 프로필 이미지 저장
- `post-images` 버킷: 게시글 첨부 이미지 저장
